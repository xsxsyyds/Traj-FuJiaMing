# 第三周：TrajNet++ 邻域与池化实验

本包使用 EPFL VITA 的 TrajNet++ baselines，包含源码、课程轨迹数据、转换脚本、训练与评价入口。无需再次下载源码或轨迹；首次安装 Python 依赖需要联网。本包不包含 Python 安装程序或可搬迁的虚拟环境。

## 1. 安装与运行

建议使用 64 位 Python 3.9 或 3.10。旧版 PyTorch 不支持所有新版 Python，不要直接使用 Python 3.12/3.13。

Windows：解压到自己的文件夹，打开该文件夹的 PowerShell，依次执行：

```powershell
py -3.9 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-classroom.txt
.\.venv\Scripts\python.exe run_classroom.py --epochs 1 --output first_check
```

若已安装 Python 3.10，可把第一行改为 `py -3.10 -m venv .venv`。依赖安装不计入训练耗时，建议课前完成。不同操作系统与芯片的旧版 PyTorch wheel 可用性需单独检查，本包实测环境为 Windows x64、Python 3.9、CPU。

请安装 `requirements-classroom.txt`，不要额外运行 `pip install -e .`：原仓库的 `setup.py` 固定 torch 1.10.0，而本课堂配置使用实测的 1.12.1。原文件保留用于追溯。

正式训练与验证：

```powershell
.\.venv\Scripts\python.exe run_classroom.py --output baseline
.\.venv\Scripts\python.exe evaluate_classroom.py OUTPUT_BLOCK/circle_classroom/lstm_social_baseline.pkl --split val
```

默认训练 10 轮、使用 CPU 两线程。每个实验请使用不同 `--output` 名称，避免覆盖已有模型。评价脚本输出 ADE、FDE、匀速外推基线以及第一条验证场景的对比图。它只加载你自己生成或信任的模型文件。

方案确定以后，将 `--split val` 改为 `--split test`，统一报告测试集结果。不要反复根据测试结果调整模型。原训练日志中的 `loss` / `test_loss` 是损失函数数值，不能直接当作 ADE/FDE；训练日志里的 `test_loss` 实际仍计算于验证集。

## 2. 作业内容与修改位置

每组完成共同基线，并选择一个修改方向。除了所研究的因素，保持划分、目标行人、随机种子、训练轮数和评价方法一致。记录 ADE、FDE、训练时间、模型参数量，解释一个改善或失效案例，不要求超过匀速基线。

| 方向 | 参数或文件 | 要回答的问题 |
|---|---|---|
| 无交互基线 | `--type vanilla` | 邻居信息是否帮助预测？此比较同时改变网络结构 |
| 邻域范围 | `--cell_side`、`--n` | 需要关注多远？ |
| 网格分辨率 | 同时调整上述两项，固定总边长 | 空间划分多细比较合适？ |
| 池化规则 | `trajnetbaselines/lstm/gridbased_pooling.py` | 同格多个邻居怎样汇总？ |
| 相同结构的信息消融 | 在池化模块中屏蔽邻居特征，重新训练 | 尽量排除网络参数量差异后，邻居是否仍有贡献？ |

示例：无交互模型 `python run_classroom.py --type vanilla --output no_neighbours`。

默认 n=4、cell_side=1，总边长为 4 个换算后坐标单位。研究分辨率时，可以对比 n=4、cell_side=1 和 n=8、cell_side=0.5。网格变细也会改变嵌入层参数量，需要在解释中说明。研究范围时应明确固定格子数还是固定单格大小，另一因素会随之变化。

请用当前虚拟环境的 Python 执行以上命令。每个机制分别训练，仅在预测时临时关闭邻居属于信息缺失敏感性实验，含义不同。

## 3. 数据说明

原始文件：`classroom/raw/circle-10m-64-1.txt`。

列顺序：行人 ID、原始帧号、x、y、附加列。附加列未使用。当前文件含 64 人、425 个连续原始帧，范围 37–461，全部轨迹同步完整。

**坐标乘以 0.01 是按厘米换算为米的待确认假设；原始帧率 25 fps 也未经元数据确认。** 在确认前，邻域和误差应解释为换算后坐标单位，不宜据此报告真实物理距离或时长。

已转换数据位于 `DATA_BLOCK/circle_classroom/`。先按采样后的时间轴划分 60%/20%/20%，再截取 8 个历史点与 12 个未来点。三个集合没有共享帧，每隔 2 个原始帧采样一次，窗口步长为 8 个采样点。

课堂小样本固定选择 ID 1、17、33、49 作为主要预测对象，其他行人仍保留为邻居。训练、验证、测试分别有 56、12、12 个场景。这些场景来自单次实验且部分窗口重叠，不是独立重复实验，也不能代表新场景泛化。时间后段可能更平稳，应避免把阶段差异解释成池化机制优劣。

`classroom/data_audit.json` 记录原始文件哈希、帧映射、划分及所有假设。转换脚本 `prepare_classroom.py` 只使用 Python 标准库，可重新生成数据；确认单位后，应同步调整坐标换算与邻域参数，并重新训练。

## 4. 源码阅读时的重要区别

本包保持上游模型与训练实现。课堂入口只固定小模型参数并调用原训练器。上游训练器会使用真实邻居未来进行教师强制，并且含远距离行人筛选。课堂评价脚本仅传入历史，所有行人的未来都由模型递推，保留全部 64 人，不使用真实未来筛选邻居；各组统一采用这个评价协议。

当前上游网格使用索引赋值填格，同格多邻居不能直接解释为标准求和池化。求和、平均、最大值等规则需在代码中明确实现，并检查空格、自己不作为邻居、同格多人的处理及梯度传播。

上游 `--front` 在当前实现中移动网格到坐标轴一侧，而相关朝向归一化代码被注释；未经修改不能直接称为行人朝向前方。若研究前向视野，应先用历史速度定义局部朝向并验证旋转行为。

CPU 小样本实验用于课堂验证想法，不等于论文完整复现。首次运行应先检查图、单位和数据划分，再讨论模型好坏。
