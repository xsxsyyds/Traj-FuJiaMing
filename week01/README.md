## 结论

**1. 五个场景分两类几何结构，后续所有分析都要分开讨论。**

- **通道型**：`seq_hotel`（约 3 m 宽的竖直走廊，y 从 −10 到 +4）和 `zara01`/`zara02`（约 4 m 宽的横向街道，y ≈ 4–7 m）。轨迹被约束在窄带内，方向高度一致，天然存在**双向对流**。
- **开阔型**：`seq_eth` 和 `students03`。行人从入口呈扇形扩散、自由选择路径，轨迹在平面内铺开，方向分散。

这个差别会直接影响 A4 的基本图：通道型场景密度高、流率可用截面法统计；开阔型场景密度低、必须用区域平均，否则 q-k 曲线会散成一片。

**2. 场景入口位置在图上可以直接读出来。** `seq_eth` 的人流从右侧 x ≈ 13 m 处扇形展开，`students03` 有两个入口（左上 x ≈ 2–4 m、右上 x ≈ 11–14 m）。A5 做瓶颈分析时，这些入口就是天然的考察点。

**3. UCY 原始标注不能直接用来算物理量——这是本次最重要的一个坑。**

UCY 官方发布的 `.vsp` 是**图像像素坐标**，不是地面平面坐标。证据有三条：

- 坐标范围恰好等于视频像素边界（720×576 居中，x ∈ [−368, 369]，y ∈ [−294, 288]）；
- 行人所在 y 位置与其像素速度显著负相关（Spearman rho = −0.33 ~ −0.48，p < 1e−4）——位置越靠上（越远）走得越"慢"，这是典型的透视压缩；
- 按像素直接当厘米算，步行速度中位数只有 0.54 m/s，明显不合理。

**处理办法**：改用学术界通行的米制转换版（行人编号与原始 `.vsp` 完全对应，148 / 204 / 434）。转换由 `datasets/build_ucy_metric.py` 完成，原始 `.vsp` 保留在同目录下备查。

若跳过这一步直接作图，UCY 三个场景的轨迹会被压成一条扁带（对比效果见 `datasets/figures/ucy_coordinate_check.png`，可用 `python datasets/check_ucy_units.py` 复现全部三条证据），A2 的速度、A3 的间距、A4 的密度全部失去物理意义。

**4. ETH 与 UCY 的坐标系不一致，跨数据集作图前必须统一。** ETH 的 `obsmat.txt` 已经是米制世界坐标；UCY 转换版同样是米制，但两者原点、朝向、正负方向都不同。所以本图每个场景独立成图，**不做跨场景叠加**。
